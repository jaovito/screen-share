# Screen Share

[![CI](https://github.com/jaovito/screen-share/actions/workflows/ci.yml/badge.svg)](https://github.com/jaovito/screen-share/actions/workflows/ci.yml)

An open-source Windows desktop publisher and browser viewer for private screen sharing among friends. Native WGC/D3D11 capture and hardware H.264 stay in Rust; the Bun control service manages identity and private room access.

**Current status: beta implementation under validation.** The connected product includes account sessions, private rooms, approved invitations, encrypted playback, an isolated Windows publisher, eight video profiles, pause/resume, signed grant renewal, opt-in system audio, adaptive quality and local diagnostics. Content keys are generated by participants and shared manually through an established encrypted channel, never through the control service. Hardware compatibility, prolonged stability and the physical two-PC game matrix remain acceptance criteria, not measurements inferred from code or CI. See [validation](docs/validation.md) and the [roadmap](PLAN.md).

## Requirements

| Tool                              | Version / purpose                                                    |
| --------------------------------- | -------------------------------------------------------------------- |
| [Bun](https://bun.sh/)            | **1.4.3**, pinned in .bun-version; dependencies, API, scripts, tests |
| [Rust/rustup](https://rustup.rs/) | **1.99.1**, pinned in rust-toolchain.toml; portable core / desktop   |
| Docker with Compose v2            | PostgreSQL, LiveKit, disposable integration tests                    |
| Git                               | Clone and contribute                                                 |

Rust needs rustfmt/clippy; rustup can download the declared toolchain. The API does not require Node. For native desktop development, use **Windows 11 x64**, MSVC C++ Build Tools, Windows SDK, and WebView2. macOS/Linux support the API, browser interfaces, and portable Rust crates. See [Windows setup](docs/development.md#windows-11-x64).

## Run locally

Start Docker, then run these commands from your terminal:

```sh
git clone https://github.com/jaovito/screen-share.git
cd screen-share
bun install --frozen-lockfile
bun run bootstrap
bun run doctor
bun run infra:up
bun run db:migrate
bun run dev
```

Open:

| Service         | Address                                                                     |
| --------------- | --------------------------------------------------------------------------- |
| Web viewer      | [127.0.0.1:5173](http://127.0.0.1:5173)                                     |
| API liveness    | [127.0.0.1:3000/healthz](http://127.0.0.1:3000/healthz)                     |
| API readiness   | [127.0.0.1:3000/readyz](http://127.0.0.1:3000/readyz)                       |
| Profile catalog | [127.0.0.1:3000/v1/video-profiles](http://127.0.0.1:3000/v1/video-profiles) |

In another terminal, `bun run smoke` checks HTTP, migrations, and authenticated LiveKit control access. It does not start or verify media.

Bootstrap creates `.env` and `infra/livekit/local.yaml` when absent, generating local secrets. It also appends missing authentication settings to an older `.env` without rotating existing keys. Keep browser and API on the same hostname (use 127.0.0.1 for both locally), because authentication uses HttpOnly SameSite cookies. Never commit either file or put secrets in VITE-prefixed variables. Infrastructure publishes only loopback ports; this setup is for local development, not internet/LAN deployment.

Stop the dev process with Ctrl+C. `bun run infra:down` stops PostgreSQL/LiveKit while preserving data. Do not delete volumes to repair a configuration problem.

### Desktop

Create an account and room, deliver a private invitation, and approve each requested participant. Prepare a session, distribute its fresh content key privately, and confirm distribution before activation. In the Windows desktop, choose a profile and explicitly select the window/monitor. Viewers enter the independent key and explicitly connect. Adding/removing an approved member retires the old media session; prepare a fresh session and independent key.

The separate [M1 command-line utility](apps/media-proof-native/README.md) and `?mode=experiment` pages remain available for controlled diagnostics.

On Windows, with the same dependencies/configuration installed:

```sh
bun run dev:desktop
```

On macOS/Linux, inspect the browser-only desktop UI instead:

```sh
bun run --filter @screen-share/desktop dev
```

The preview at [127.0.0.1:1420](http://127.0.0.1:1420) has no native IPC or capture engine. See [desktop instructions](apps/desktop/README.md).

### Container API

Stop the host API before switching modes because both use port 3000:

```sh
bun run stack:up
bun run --filter @screen-share/viewer-web dev
bun run smoke
```

The container runs a standalone Bun executable. Each stack:up runs a fresh migrator before API startup. `bun run stack:down` removes containers/network and preserves database volumes. See [API instructions](apps/control-api/README.md).

## Troubleshooting

- **Wrong Bun version:** activate the version in .bun-version and rerun doctor.
- **Docker unavailable:** start Docker Desktop/OrbStack and check docker info.
- **Readiness returns 503:** start infra and run db:migrate; HTTP never applies schema changes.
- **Port 5173 busy:** set VIEWER_PORT to a free port and update CORS_ORIGINS in .env, then restart API/viewer.
- **Port 3000 busy:** stop the previous host/container API mode before switching.
- **PostgreSQL password mismatch:** changing .env does not update a password in an initialized volume. Coordinate credential changes with the database; do not erase data.
- **LiveKit credentials mismatch:** align the generated local file with an intentional credential rotation; bootstrap preserves existing files.
- **Native SDK ICE fails locally:** loopback-only Compose is the control/development baseline. Native WebRTC ignores loopback interfaces and needs an explicitly routable private SFU address for same-machine testing. The disposable media test checks this prerequisite and fails when the Docker runtime cannot route its private interface. Use the documented HTTPS/WSS/TURN deployment for other computers; changing only a frontend URL does not provide connectivity.

More details: [development guide](docs/development.md), [explicit self-hosted deployment](docs/deployment.md), and [signed release preparation](docs/releases.md). These production workflows require operator DNS/TLS/signing configuration and are separate from the local stack.
